# Pass criteria

What "proving" a topic means, and how revisits are scheduled. Early notes; every value here is deliberately left open until tested (see [Evaluation](evaluation.md)).

## The bar

A topic counts as done when you show real understanding on real problems, scored against a visible rubric. You work the problems first; the pass check comes after.

## Open questions

- How many problems, of what mix?
- How strict is the explain-back?
- What is the revisit target, and which scheduling algorithm sets it? (Candidate: FSRS.)
- How are arithmetic and units checked? (Proposal: a small worker using symbolic and unit-aware libraries, not the language model.)

## Fixed rules apply the bar

Proposed, not yet decided: the model scores answers, but fixed code applies the bar and schedules the revisit. See [Decisions](decisions.md).
